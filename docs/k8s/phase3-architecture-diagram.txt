═══════════════════════════════════════════════════════════════════════════════
                         SCALING BEHAVIOR
═══════════════════════════════════════════════════════════════════════════════

SCALE-UP (Aggressive):
  0 tasks → 0 workers (scale-to-zero)
  Tasks appear → Workers spawn immediately
  0→10→20→40→50 in ~60 seconds
  Policy: 100% increase every 15s OR +10 pods (whichever is higher)

SCALE-DOWN (Gradual):
  No tasks for 5 minutes → Start scale-down
  40→20→10→5→0 over 4 minutes
  Policy: 50% decrease every 60s OR -5 pods (whichever is lower)

═══════════════════════════════════════════════════════════════════════════════
                         DATA FLOW
═══════════════════════════════════════════════════════════════════════════════

1. Task Creation:
   User/System → Coordinator Master → Task Queue (file system)

2. Prometheus Detection:
   Task Queue → Prometheus scrapes → cortex_task_queue_depth metric

3. KEDA Scaling Decision:
   Prometheus ← KEDA polls (every 15s)
   KEDA → HPA → Scale worker deployment

4. Worker Processing:
   Worker spawns → Claims task (atomic rename)
   Worker → Processes task → Records result
   Worker → Exits (or waits for next task)

5. Scale-to-Zero:
   No tasks for 5 min → KEDA cooldown expires
   KEDA → HPA → Scale to 0 replicas

═══════════════════════════════════════════════════════════════════════════════
                         HIGH AVAILABILITY
═══════════════════════════════════════════════════════════════════════════════

Masters:
  • Pod anti-affinity (prefer different nodes)
  • Automatic restart on failure
  • Persistent state (10GB per master)
  • Shared coordination volume

Workers:
  • Stateless (can restart on any node)
  • Graceful shutdown (finish task before exit)
  • Automatic replacement by deployment
  • Scale based on demand

Storage:
  • PersistentVolumes with Retain policy
  • ReadWriteMany for shared coordination
  • ReadWriteOnce for master state
