## What is RAG vs CAG?

### RAG (Retrieval Augmented Generation) - v1.0-v4.0
**How it worked**:
1. Query arrives
2. Search vector database for relevant documents
3. Retrieve top-K matching chunks
4. Pass to LLM with query
5. Generate response

**Limitations**:
- Every decision required retrieval (~150-200ms latency)
- Repeated lookups for static knowledge
- Token waste on re-loading same context

### CAG (Cache Augmented Generation) - NEW in v5.0
**How it works**:
1. At initialization: Load ALL static knowledge into model context
2. Model processes and stores in KV cache
3. Query arrives
4. Model accesses cached knowledge instantly (~5-10ms)
5. Generate response

**Benefits**:
- Zero retrieval latency for static knowledge
- One-time loading cost
- 95-97% faster decisions

### Hybrid RAG + CAG - v5.0 Strategy
**Use CAG for** (static, frequently-accessed):
- Worker type specifications
- Coordination protocols
- MoE routing rules
- Token budgets
- SLA thresholds
- EM trigger criteria

**Use RAG for** (dynamic, growing):
- Historical worker outcomes
- Vulnerability history
- Implementation patterns
- Routing decision log

## Migration Guide

### For Existing Masters
Masters automatically benefit from CAG caching - no code changes needed!

1. **Initialization**: Master loads static-knowledge.json into context
2. **Runtime**: Master references cached knowledge instead of file I/O
3. **Fallback**: If cache missing, degrades gracefully to RAG

### For New Masters
To add a new master with CAG support:

1. Create cache file: `coordination/masters/{new-master}/cag-cache/static-knowledge.json`
2. Add CAG section to master prompt: `agents/prompts/{new-master}.md`
3. Update `scripts/cag/load-cache.sh` to include new master

## Known Limitations

1. **CAG cache size**: Limited by model context window (~100k tokens)
   - Current usage: ~13k tokens (13% of budget)
   - Room for growth: ~87k tokens available

2. **Vector DB**: Currently mock implementation
   - Real embeddings require Python dependencies
   - Linear scan limits to ~10k documents
   - Need FAISS for larger scale

3. **Cache invalidation**: Manual regeneration required
   - No automatic detection of stale caches
   - Future: Add cache versioning and auto-refresh
