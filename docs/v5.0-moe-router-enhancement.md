## Problem Addressed

### v4.0 Routing Issues

In v4.0, the MoE router relied solely on keyword matching within task descriptions. This caused significant misrouting:

**Example failure case**:
```
Task: "security-scan: Scan commit-relay repository for vulnerabilities"

v4.0 Routing:
- Keyword matching: "scan" (1 match out of 16 security keywords)
- Security confidence: 3%
- Development confidence: 0%
- **Result**: Routed to development master ❌

Root cause: Hyphenated compound words ("security-scan") don't match
word-boundary grep patterns (\b scan \b)
```

### Impact

- **50%+ misrouting rate** for tasks with hyphenated types
- Manual intervention required to correct routing
- Broken Phase 1 validation workflow
- Poor user experience

## Solution: Type-Based Routing with CAG Integration

### Architecture

The v5.0 enhancement adds **type-aware routing** that extracts and analyzes the task type field before falling back to keyword matching:

```
Task Description Format: "<type>: <title> <description>"
                          ^^^^^^
                          Extracted for type-based routing
```

### Routing Flow

```
┌─────────────────────────────────────────────────────────────────┐
│  1. Extract Task Type from Description                         │
│     Regex: ^([a-z0-9-]+):                                       │
│     Example: "security-scan: ..." → type = "security-scan"     │
└─────────────────────────────────────────────────────────────────┘
                              ↓
┌─────────────────────────────────────────────────────────────────┐
│  2. Type Normalization (CAG-Enhanced)                           │
│     - "cve-2024-1234" → "cve"                                   │
│     - "vulnerability-xyz" → "vulnerability"                     │
│     - "security-scan" → "security-scan" (no change)             │
└─────────────────────────────────────────────────────────────────┘
                              ↓
┌─────────────────────────────────────────────────────────────────┐
│  3. Type-to-Master Mapping (95% confidence)                     │
│                                                                 │
│  security-scan → security (95%)                                 │
│  security-audit → security (95%)                                │
│  cve-* → security (95%)                                         │
│  feature → development (95%)                                    │
│  bug-fix → development (95%)                                    │
│  inventory → inventory (95%)                                    │
│  build → cicd (95%)                                             │
└─────────────────────────────────────────────────────────────────┘
                              ↓
┌─────────────────────────────────────────────────────────────────┐
│  4. Keyword-Based Scoring (fallback for ambiguous cases)        │
│     - Still runs keyword matching                               │
│     - Type-based score (95%) overrides if higher                │
│     - Provides backup for tasks without clear types             │
└─────────────────────────────────────────────────────────────────┘
                              ↓
┌─────────────────────────────────────────────────────────────────┐
│  5. Final Routing Decision                                      │
│     - Primary expert selected                                   │
│     - Confidence score calculated                               │
│     - Routing strategy determined                               │
└─────────────────────────────────────────────────────────────────┘
```

## Known Limitations

1. **Task type required**: Tasks without type prefix fall back to keyword matching (35% avg confidence)
2. **Case-sensitive types**: Only lowercase types matched (e.g., "Security-Scan" won't match)
3. **No fuzzy matching**: Typos in type field not handled (e.g., "securtiy-scan" → development)

### Future Enhancements

1. **Fuzzy type matching**: Handle common typos
2. **Dynamic CAG loading**: Load routing rules from cache at runtime
3. **ML-based confidence**: Learn optimal confidence scores from outcomes
4. **Auto-correction**: Suggest correct type for misformatted tasks
