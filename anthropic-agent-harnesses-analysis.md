# Anthropic: Effective Harnesses for Long-Running Agents

**Source:** https://www.anthropic.com/engineering/effective-harnesses-for-long-running-agents
**Date Analyzed:** 2025-12-04

## Overview

Anthropic's engineering practices for building effective harnesses for long-running agents that work across multiple context windows, inspired by human software engineering practices.

---

## Core Architecture

### Two-Part Agent Design

1. **Initializer Agent**: Handles first-run setup with specialized prompting
2. **Coding Agent**: Manages incremental progress in subsequent sessions

This separation ensures proper project scaffolding while enabling continuous development across sessions.

---

## Key Architectural Components

### Environment Setup

The initializer agent creates three critical artifacts:

1. **init.sh script**: Enables quick environment startup
2. **claude-progress.txt**: Documents agent work history between sessions
3. **Initial git commit**: Establishes baseline code state

### Feature Management

A JSON-based feature list prevents premature project completion. The system specifies granular requirements (200+ features for a claude.ai clone) marked as "failing" initially.

**Critical instruction:**
> "It is unacceptable to remove or edit tests because this could lead to missing or buggy functionality"

This prevents agents from declaring victory by removing failing tests.

---

## Failure Mode Mitigation

| Problem | Solution |
|---------|----------|
| Agent attempts entire project at once | Structured feature list enforces single-feature focus per session |
| Undocumented progress between sessions | Git commits + progress file provide continuity |
| Premature completion marking | Mandatory end-to-end testing before marking features passing |
| Environmental setup delays | Pre-written init.sh script eliminates discovery time |

---

## Session Startup Pattern

Each coding session follows a standardized sequence:

1. Verify working directory
2. Review git logs and progress documentation
3. Select highest-priority incomplete feature
4. Run basic end-to-end validation
5. Begin incremental development

This pattern ensures continuity and prevents redundant work.

## Testing Integration

**Browser Automation**: Puppeteer MCP proved essential for identifying real-world bugs that unit tests missed.

**Known Challenges:**
- Vision limitations in UI testing
- Modal detection gaps
- End-to-end validation complexity

---

## Best Practices

### 1. Granular Feature Decomposition
Break projects into 200+ atomic features rather than broad milestones. This prevents agents from skipping details.

### 2. Session Continuity Mechanisms
- Git commits for code state
- Progress files for context
- Feature list for tracking

### 3. Forced Validation
Require end-to-end tests before marking features complete. Unit tests alone miss integration issues.

### 4. Environmental Reproducibility
Pre-configure environment setup scripts so agents don't waste tokens on discovery.

### 5. Explicit Progress Documentation
Maintain `claude-progress.txt` with:
- What was accomplished
- Current blockers
- Next steps

---

## Future Directions

The team anticipates exploring **multi-agent architectures** with specialized agents for:
- Testing
- QA
- Code cleanup

This may yield better performance than single general-purpose agents across extended development cycles.

## Applicability to Cortex

### Direct Alignment

Cortex already implements several of these patterns:

✅ **Multi-session architecture**: Master-worker pattern with persistent state
✅ **Progress tracking**: `coordination/task-queue.json`, `dashboard-events.jsonl`
✅ **Git integration**: Workers operate on git repositories
✅ **Specialized agents**: 5 master types, 7 worker types

### Gaps to Address

❌ **No progress.txt equivalent**: Workers don't maintain human-readable session logs
❌ **No init.sh pattern**: Environment setup isn't pre-scripted for workers
❌ **Limited feature granularity**: Tasks may not be decomposed to 200+ atomic units
❌ **No end-to-end validation requirement**: Workers don't enforce e2e tests before completion

---

## Recommendations for Cortex

### 1. Add Worker Progress Logs
Create `coordination/workers/{worker-id}/progress.txt` that documents:
- Session start/end times
- Files modified
- Tests run
- Blockers encountered
- Next intended actions

### 2. Implement Init Scripts
Add `coordination/workers/{worker-id}/init.sh` generated by master agents containing:
- Environment variables
- Dependencies to install
- Repository setup commands
- Test commands

### 3. Enforce Feature Granularity
Enhance the Coordinator master to decompose tasks into atomic units:
- Break "implement authentication" into 50+ subtasks
- Track each in a feature list JSON
- Require completion evidence for each

### 4. Add Validation Gates
Update worker completion criteria:
- Must run relevant test suite
- Must perform end-to-end validation
- Must document test results in completion report
- Cannot mark complete if tests fail

### 5. Enhance Session Continuity
Extend `worker-pool.json` to include:
```json
{
  "worker_id": "worker-implementation-001",
  "session_history": [
    {
      "session_id": "session-001",
      "started_at": "2025-12-04T10:00:00Z",
      "ended_at": "2025-12-04T10:15:00Z",
      "progress_file": "coordination/workers/worker-implementation-001/session-001-progress.txt",
      "git_commits": ["abc123", "def456"]
    }
  ]
}
```

### 6. Implement Multi-Agent QA Pattern
Add new worker types:
- `qa-worker`: Validates implementation worker output
- `test-worker`: Generates and runs comprehensive tests
- `cleanup-worker`: Refactors code post-implementation

---

## Key Takeaways

1. **Session continuity is critical**: Progress files and git commits bridge context windows
2. **Granular feature lists prevent premature completion**: 200+ atomic tasks vs. 10 broad milestones
3. **Pre-scripted environments save tokens**: init.sh eliminates discovery overhead
4. **End-to-end testing catches real bugs**: Unit tests alone are insufficient
5. **Multi-agent specialization shows promise**: QA, testing, and cleanup as separate concerns

Cortex already has strong architectural alignment with these patterns. The main opportunities are adding explicit progress documentation, environment initialization scripts, and validation gates.
